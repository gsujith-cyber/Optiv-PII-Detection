2.1: SQL Injection Vulnerability in WHERE Clause Allowing Retrieval of Hidden Data

Platform:
Port Swigger Web Security Academy

Tools Used:

[PERSON_3] Professional
Firefox

Vulnerability Description:
The web application uses a category parameter to filter products. User input is not properly sanitized before being included in an SQL query. This allows an attacker to modify the SQL query and retrieve hidden data.

Procedure:
 Step 1:  Access the Lab
Opened the PortSwigger Web Security Academy lab and launched the target application.


Step 2:  Intercept the Request
Navigated to the "Corporate Gifts" category and captured the request using [PERSON_3].


Step 3:  Test and Exploit the Vulnerability
Modified the category parameter by adding a single quote (') to check for SQL Injection behavior.
The following payload was injected into the category parameter:
Corporate gifts' OR 1=1--
Modified Request:
GET /filter?category=Corporate+gifts'+OR+1=1—



Step 4: Observe the Response
After sending the modified request through [PERSON_4], the application displayed products from all categories, including hidden products.

Step 6: Lab Completion
The application returned a successful response and the lab was marked as solved.


Impact:
An attacker can retrieve unauthorized data from the database by manipulating SQL queries. This may lead to information disclosure and further compromise of the application.
Remediation:
1. Use parameterized queries (Prepared Statements).
2. Validate and sanitize user input.
3. Apply least-privilege database permissions.
4. Implement secure coding practices.
5. Perform regular security testing.

Result:
Successfully exploited a SQL Injection vulnerability in the WHERE clause and retrieved hidden data. The lab was completed successfully.

Conclusion:
This lab demonstrated how improper input validation can lead to SQL Injection vulnerabilities. By manipulating the category parameter, hidden data was retrieved from the backend database, highlighting the importance of secure query handling.
